## Featured work
 
### Sarvoday Solar CRM · client project, live since October 2026
 
**The problem:** About 280 customers were kept in a 21-sheet Excel workbook. The same customer appeared more than once, phone numbers were typed in different ways, and nothing reminded the team whom to call and when.
 
**What I built:** One shared list that works on a phone and says whom to call each day: one-tap follow-ups, a reminder bell, search by a phone number typed any way, duplicate warnings, a "Needs review" list that says what's missing, and a dashboard for the owner.
 
**The hard part:** Moving the Excel data without losing or changing anything. The import does a trial run and writes a full report before saving, merges duplicates, keeps the original text, and flags unclear records instead of guessing.
 
**Running it safely:** On an AWS server in the client's own name, with nightly backups, a weekly automatic restore test and an alert if a backup fails.
 
**Built with:** Python, Django, PostgreSQL, HTMX, Alpine.js, Tailwind CSS, Docker Compose, Caddy, AWS Lightsail.
 
[Case study](https://builtbyatharva.com/work/sarvoday-crm) · The app is private (login only).

## How I work with AI
 
I use Claude Code to write most of the code. I decide what gets built and how it should work, check what it produces, test the screens myself, and handle the server setup and launch.
 
The tools are fast, but they make mistakes their own tests don't catch. In the Sarvoday CRM, every automated test passed while the notification bell only flashed instead of opening its list. I found that, and other problems, by testing the screens myself. That kind of checking is part of how I work.
